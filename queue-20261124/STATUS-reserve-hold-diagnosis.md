# 예약 홀드 진단 (v0.3.53 기준)

상태: awaiting
착수: 2026-11-26
범위: 진단 + 수리 구현·테스트·번들·커밋까지. 출시는 하지 않는다.

## 사안
기온 예약 슬롯 1이 설정돼 있는데도 2026-11-26 01:27 KST에 메인 매수(스페인 PP Yes @0.76, $5.06)가 먼저 나가, 현금 약 $8.67 → $3.61로 줄어 그날 기온 $6 진입이 불가능해졌다. 예약 홀드(메인 매수 차단)가 왜 현금을 지키지 않았는지 코드로 특정한다.

## 최종 판정 (2026-11-26)

원인은 하나로 특정된다: **기온 이벤트 조회의 부분 실패가 홀드 해제와 무로그로
맞물린 설계 결함.** 그날 밤 폰 조회에서 내일분(조회 순서상 뒤 40개)이 통째로
빠진 채 오늘분만 성공하면, 전수 실패가 아니라 tempFetchFailed가 서지 않고,
hasUpcomingWindow는 빈 목록에 false라 홀드가 풀렸다. 부분 실패를 성공으로
취급한 것(v0.3.39 감사 E에서 전수 실패만 안전 방향으로 돌린 잔여 구멍)이
코드 쪽 결함이고, 해제 시 로그가 없어 사후에 드러나지 않은 것이 두 번째 결함이다.
당일 네트워크 부분 실패 자체는 폰 회선 상태라 코드로 재현할 수 없으나, 결함의
본체(부분 실패 → 무음 해제)는 코드에 있고 아래 수리로 닫았다.

추적 지점별 답:
1. 홀드 판정: 조회 범위 오늘+내일(UTC) 80슬러그, 내일 이벤트는 전날 저녁부터
   판정에 걸리는 것이 설계·테스트·실측(Gamma 생성 시각 이틀 전 05:11 UTC,
   시장 활성)으로 확인됐다. 사건 시각(11-25 16:27 UTC) 재구성 시뮬레이션에서
   hasUpcomingWindow=true.
2. 실행 순서: 홀드 평가는 기온 스캔과 같은 사이클에서 선정 패스 직전에
   양쪽 엔진 모두 동일하게 돈다. 메인만 도는 사이클은 없다 (사이클 60초).
3. 현금 하한 가드: cashFloor = max($2.87, 평가금×30%)만 지킨다. 사건 시점
   평가금이 낮아(기온 포지션 정산 뒤) cashFloor ≤ $3.67이었고, $8.67 − $5.06 =
   $3.61 ≥ cashFloor라 허용한 것은 설계대로다. 기온 예약분($6+$2.87)을 지키는
   장치는 슬롯 홀드가 유일했는데 그게 풀려 있었다.
4. 로그: 종전에는 홀드 해제·미작동이 로그에 전혀 남지 않았다 (남는 건 전수
   실패 유지, 홀드 중 차단 발생, 차선 현금 부족뿐). 사용자 피드백 규칙 위반으로
   수리에 포함했다.

## 수리 (양쪽 엔진 패리티)
- 조회가 실패 건수를 돌려준다 (예외 + 빈·비배열 응답 = 존재 미확인 슬러그).
  전수 실패는 종전대로 null.
- 부분 실패(tempFetchIncomplete)면 홀드를 유지한다 (안전 방향). 사유 로그:
  "기온 이벤트 조회 일부 실패 (N건) — 이번 사이클은 기온 예약을 유지합니다",
  차단 발생 시 "기온 예약 — 조회 일부 실패로 메인 N건을 미루고…".
- 홀드 해제 전이 로그: "기온 예약 해제 — 진입 창이 남은 이벤트가 없어 메인
  차단을 풉니다" (켜짐→꺼짐 전이에서만).
- 동작 변화 주의: 슬러그가 영구히 사라진 도시가 생기면 조회가 계속 불완전해
  홀드가 유지되고 메인 매수가 미뤄진다. 로그에 사유가 남으므로 도시 목록
  갱신으로 풀 수 있다.

## 제안 (미구현, 사용자 결정 사항)
- 최후 방어선으로 현금 기준 차단: 홀드와 무관하게, 기온 ON + 예약 > 0이면
  메인 매수 후 현금이 기온 건당 + 예비금 아래로 내려가지 않게 하는 가드.
  홀드 판정 신뢰성과 별개로 현금을 직접 지키지만, 메인 매수 기회를 줄이는
  정책 변경이라 결정이 필요하다.

## 중간 판정 (2026-11-26)
- 홀드 판정식·드라이버 배선·설정 해석·조회 범위(오늘+내일)는 양쪽 엔진 모두 정상.
  실제 Gamma 페이로드(11-26 이벤트, 사건 시각 11-25 16:27 UTC로 재구성)로 JS 순수 판정을
  돌리면 hasUpcomingWindow=true, 네이티브 드라이버 테스트 356건(전날 저녁 홀드 포함) 통과.
- 수치 대조: 현금 $8.67·메인 건당 $5·현금 하한 ≤ $3.67이면 sizing 슬롯은 정확히 1.
  홀드가 켜진 상태에서는 메인 매수가 수학적으로 불가능하고, 슬롯 0이면 매수 자체가 없다.
  따라서 사건 사이클에서는 tempHold=false였다는 것이 유일하게 가능한 결론.
- 설정(ON·예약 1)이 주어진 조건에서 tempHold=false가 되는 경로는 하나뿐이다:
  조회가 전수 실패가 아닌데도 조회 목록에 창이 남은 후보 가능 이벤트가 하나도 없는 경우.
  실제 Gamma에서 11-26 이벤트는 11-24 05:11 UTC에 시장 활성 상태로 생성돼 사건 시각에
  조회 가능했다(실측). 즉 그 사이클의 조회는 부분 실패였어야 한다 — 조회 순서가
  오늘 40개 → 내일 40개라, 중간부터 실패가 몰리면 홀드 의존분(내일)이 정확히 지워진다.
- 결함 지점: 부분 실패를 성공으로 취급하는 설계(전수 실패만 안전 방향) + 홀드 해제 시 무로그.
  현금 하한 가드는 cashFloor(최대 $2.87·평가금 30%)만 지키는 설계라 $5.06 매수를 허용한 것
  자체는 설계대로다. 1차 방어는 슬롯 홀드뿐이었다.
- 수리 방향: 조회 불완전(부분 실패 포함)이면 홀드 유지 + 사유 로그, 홀드 해제 전이 로그.

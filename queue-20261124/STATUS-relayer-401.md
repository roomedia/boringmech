# STATUS: relayer 401 리딤 실패 조사

- 상태: awaiting (원인 판정·앱 측 수정·가드 테스트 완료, 출시 별도 지시 대기. 자격증명 재발급은 동호 절차로 분석 문서에 명시)
- 시작: 2026-11-25 08:55 KST
- 증상: 제보 id 44, 사이클 294부터 매 사이클 리딤 제출이 relayer HTTP 401 invalid authorization으로 실패. 정산 포지션 발생으로 보유 8→7, 현금 회수 막힘.

## 단계
- [x] 1. 제보 판독: 실패 시작 v0.3.49 사이클 294 (2026-11-25 08:22:38), 보유 8→7 직후 첫 리딤 시도부터 401. id 43 (v0.3.48)에는 리딤 시도 자체가 없음. 온체인 마지막 REDEEM은 2026-11-15 (키 등록 11-19 이전)이라, 키 등록 후 첫 제출 시도가 이번 건일 가능성이 높음.
- [x] 2. 코드 경로: 네이티브 RedeemSubmitter (relayer-v2.polymarket.com, 헤더 RELAYER_API_KEY/RELAYER_API_KEY_ADDRESS, GET params → POST /submit). v0.3.29 이후 무변경, .45~.49 diff는 이 경로를 건드리지 않음 (앱 회귀 아님). 자격증명은 bm_relayer (enc1: 암호문, 네이티브 미러), 매 회차 새로 읽음. 등록 검증은 형식뿐, EOA 대조 없음.
- [x] 3. 공식 문서 대조: 헤더 규격·엔드포인트는 현행 문서와 일치. 키는 polymarket.com → Settings → API Keys → Relayer API Keys에서 생성하고, 생성 시 표시되는 Signer Address와 API Key 쌍을 저장해야 함. nonce 조회(params)는 무인증 공개 엔드포인트라 GET 성공은 키 유효성을 증명하지 못함 — 첫 인증 호출인 POST /submit에서 401이 터진 것과 정합.
- [x] 4. 원인 판정: 저장된 (키, 주소) 쌍이 이 계정의 유효한 소유자 쌍이 아님 (자격증명 측 문제). 세부 후보: 주소에 Signer Address가 아닌 주소 (예: 입금 지갑 주소) 입력, 다른 계정에서 만든 키, 키 오타, 키 삭제·폐기. 값 없이는 세부 특정 불가. 앱 방식 불일치·회귀는 배제.
- [x] 5. 앱 측 수정 완료: ① 등록 시 EOA 대조 (다르면 저장 거부) + 주소 칸 안내를 Signer Address로 명시 + 발급 경로 안내 추가 ② 401 래치 (같은 자격증명 재제출 중단, 하루 1회 보류 로그, 재등록 시 지문 변경으로 자동 해제) ③ 가드 테스트 JS 18건·네이티브 6건. 출시는 하지 않음.
- [x] 6. 검증: JS 전 슈트 통과, NativeCycleTest 344, 골든 1~4 전부, 축소 스모크 PASSED. 실물 리딤 성공은 새 키 등록 + 출시 후 제보 로그로만 확정 가능 (한계 명시). 산출: relayer-401-analysis.md (발급 경로 정본과 동호 재등록 절차 포함)

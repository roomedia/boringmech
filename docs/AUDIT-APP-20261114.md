# boringmech 앱 감사 — 2026-11-14 (대상 v0.3.2 → 수정 v0.3.3)

pstack 전제 공격 방식: 전제를 목록화하고 각각 실측·코드 대조로 판정했다.
판정: 성립 / 부분 / 붕괴 / 미검증. 붕괴와 부분 중 돈이 새는 경로는 v0.3.3에서 수정했다.
실주문 테스트는 하지 않았다 (throwaway 키, 조회·서명 경로만 실측). 실기기·에뮬레이터가 없어 WebView 실구동은 미검증으로 남긴다.

## 판정표

| # | 전제 | 판정 | 근거 |
|---|---|---|---|
| 1 | file:// 오리진(null)에서 API 호출이 된다 | **성립** | curl로 `Origin: null` 재현 — Gamma `ACAO: *`, CLOB preflight가 `poly_api_key·poly_signature·poly_timestamp·poly_passphrase` 인증 헤더를 허용(204), Data API v2 `ACAO: *`, Polygon RPC 4개 중 2개(publicnode·drpc) `ACAO: *` + 폴백 구조. 단, `fetchJson`의 `User-Agent` 헤더는 브라우저가 버리는 금지 헤더라 실기기에서는 실리지 않는다(무해 — Node 검증과의 차이 지점). WebView 자체의 실구동은 미검증 |
| 2 | 방금 산 마켓을 다시 사지 않는다 | **부분** | 성공 경로는 성립: `markBought`가 localStorage에 영속되고, 매 사이클 `boughtSlugs()`를 새로 읽어 후보에서 제외한다. 재시작·자동재개 후에도 유지된다. 구멍은 "제출됐으나 결과를 모르는" 경로 — 전제 5와 같은 뿌리, 함께 수정 |
| 3 | 사이클이 겹쳐 이중 주문이 나지 않는다 | **붕괴(조건부)** | 타이머는 순차 실행이라 겹치지 않고 `start()` 연타도 `state.running` 가드로 막힌다. 그러나 **정지 직후 재실행**하면, 진행 중이던 구 사이클이 `running`이 다시 true가 된 것을 보고 stale 스냅샷·stale 슬롯으로 이어 사는 창이 있었다 |
| 4 | 포그라운드 서비스가 targetSdk 34에서 동작한다 | **성립** | 매니페스트에 `foregroundServiceType="dataSync"` + 권한 5종(FOREGROUND_SERVICE·FOREGROUND_SERVICE_DATA_SYNC·WAKE_LOCK·POST_NOTIFICATIONS·INTERNET) 선언을 APK badging·xmltree로 확인. `startForeground`에 타입을 명시해 호출한다. 알림 권한이 거부돼도 서비스는 유지되고 알림만 숨겨진다(코드 경로상 안전). 실기기 동작은 미검증 |
| 5 | 자동 재개가 제출 결과를 모르는 주문을 중복 제출하지 않는다 | **붕괴** | `postOrder`가 네트워크 오류 등으로 예외를 던지면(주문이 실제로는 체결됐을 수 있는 상태) `markBought`가 호출되지 않아, 다음 사이클·재개 후 같은 마켓을 다시 살 수 있었다. 또 `success === false`인데 `errorMsg`가 비어 있으면 성공으로 오인할 수 있었다 |
| 6 | 사이징 경계에서 bet·slots가 음수·NaN으로 흐르지 않는다 | **부분** | 정상 경계는 단위 검증으로 성립(잔고 0 → 슬롯 0, 보유 75건 → 0, 현금 < 현금하한 → 투입 0). 그러나 입력이 NaN이면 `slots`도 NaN이 되고 `slots < 1` 비교가 false라 게이트를 통과해 최대 검증 상한(60건)까지 사는 경로가 있었다 |
| 7 | 개인키 localStorage 평문 저장이 허용 가능하다 | **부분 (미수정 — 후속)** | WebView localStorage는 앱 전용 샌드박스라 다른 앱은 못 읽지만, 루팅·디버그 백업 추출에는 평문으로 노출된다. Android Keystore로 암호화 키를 감싸는 브리지 이관은 기술적으로 가능하나, 실기기 검증 없이 키 접근 경로를 바꾸면 연동 자체가 깨질 위험이 현행 위험보다 크다고 판단해 이번 범위에서는 하지 않는다. 후속 과제로 명시 |
| 8 | deposit wallet 탐지의 동률 선택이 결정적이다 | **성립** | 양쪽(beacon·UUPS) 다 배포된 경우 pUSD 잔고가 큰 쪽을 고르고, 동률(양쪽 0 포함)이면 beacon이 이긴다 — 후보 순서가 beacon 먼저이고 교체 조건이 엄격히 `>`라서 결정적이다 |

## 부수 발견

- Polygon RPC 목록의 blastapi 엔드포인트가 서비스 종료 상태(403 "no longer available")였다. 죽은 항목은 폴백 지연만 늘리므로, 실측으로 살아 있고 `ACAO: *`를 확인한 OnFinality 공개 엔드포인트로 교체했다.

## v0.3.3 수정 (전부 `app/src/engine.js`)

1. **세대 가드** (전제 3): `state.gen` 도입. `start()`·`stop()`이 세대를 올려 진행 중 사이클을 무효화하고, `loop`·`runCycle`은 자기 세대가 현재 세대일 때만 계속한다. 정지→재실행 레이스에서 구 사이클이 이어 사는 창을 닫았다.
2. **주문 결과 불명 처리** (전제 5·2): `postOrder` 예외 시 체결됐을 수 있다고 보고 `markBought`로 기록해 중복 매수를 막는다(로그에 "주문 결과 불명 — 중복 방지 기록"으로 드러나게 남긴다). 확정 거부는 `errorMsg`뿐 아니라 `success === false`도 분리해 기록 없이 다음 후보로 넘긴다. 서명 실패(createOrder)는 제출 전이라 기록하지 않는다.
3. **사이징 fail-closed** (전제 6): 입력 중 하나라도 비유한(NaN·Infinity)이면 슬롯 0으로 닫는다 — 측정값을 못 믿으면 사지 않는다.
4. **죽은 RPC 교체** (부수 발견): blastapi → OnFinality.

## 검증 증거

- CORS: 위 표의 curl 실측 (전제 1).
- 사이징 단위 검증 10케이스: 기존 기준 케이스(57.87→8슬롯 등 live_executor 일치) + 경계(잔고 0·보유 초과·현금 부족) + 비유한 입력(NaN·Infinity·undefined → 슬롯 0).
- 세대 가드·결과 불명 기록: 소스 배선 정적 검증(호출 위치·조건) + 정렬 회귀 5/5 + 실행 의도 회귀 12/12.
- 동적 겹침 재현(모의 CLOB 클라이언트 하네스)은 만들지 않았다 — 수정은 구조로 닫았고 동적 검증은 미검증으로 남긴다.

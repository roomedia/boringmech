## live/live_executor.py 상세

- 자체 명세 `live/SPEC.md`가 정본인 소액 실전 실험이다. 목적은 수익이
  아니라 실체결·슬리피지 실측이고, 시작 자본은 $57.87이다.
- 앱 규칙과 의도적으로 다른 값이 있다 (SPEC 확정 사항이라 동기화 대상이
  아니다): 검증 밴드 0.70~0.90 (앱·페이퍼 풀 밴드는 0.60~0.90), 사이징
  총자본 1%·하한 $5 (앱은 $5 고정). 게이트에는 고정값(pinned)으로 박아
  이 값들에서 더 drift하면 실패하게 했다.
- 실행 상태 (2026-11-27 확인): 사이클 훅은 초안
  (`~/hooks/scripts/boringmech-live.sh.draft`)만 있고 등록되지 않았다.
  실행 디렉토리(`pm-trader/boringmech-live/`)에 LIVE_ENABLED 파일이 없고,
  state.json 최종 갱신은 2026-11-14, 체결·보유 이력은 0건이다. 2026-11-11
  실주문 시도 1건은 지역 차단 403 fail-safe로 중단됐다.
- 주의: 실행 디렉토리 사본은 레포 사본보다 낡았다 (고정 $5 사이징,
  2026-11-13 시점). 재가동하려면 먼저 레포 사본으로 교체하고
  LIVE_ENABLED 게이트 절차를 다시 밟아야 한다.

## 동기화 의무 범위

- 공유 판단 상수(손절폭, 밴드, 사이징, 기온 수치, 리딤 허용 오차 등
  게이트 목록)만 맞춘다. 값이 바뀌면 정본(JS)부터 바꾸고 나머지를
  따라가게 하며, 게이트가 어긋남을 잡는다.
- 로직 동기화 의무는 없다. Python 트랙은 페이퍼 평가와 연구 전용이고,
  출하본의 규칙 변경이 Python 로직 변경을 강제하지 않는다. 단, 상수가
  어긋난 채면 페이퍼 평가가 출하본과 다른 규칙으로 측정되므로 상수만은
  끊지 않는다.
- 작업 디렉토리 사본들은 이 레포 밖이라 게이트 범위 밖이다. 레포 사본의
  상수를 바꿀 때는 작업 디렉토리 사본에도 같은 변경을 넣어야 평가가
  어긋나지 않는다.
